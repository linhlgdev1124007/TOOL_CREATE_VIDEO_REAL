# Wrydeco Reels

Workspace: resolve three parents above this skill directory. The runtime is `.venv-reels/Scripts/python.exe`; pipeline is `reels/pipeline.py`. All commands below run at workspace root. Read root `README.md` and `references/edit-plan.md` before creating a job. The current user brief takes priority over old demo conventions.

## One request, one finished Reel

Accept a local media folder, plus optional brief/duration. Default source is `source/Wrydeco_real`, style is warm, premium and rhythmic, US English, 720×1280 at 30 fps, 18–25 seconds including the mandatory Wrydeco outro. Only use voice, chill instrumental music and 2–4 meaningful SFX accents. Completely mute all source media, including original outro audio. Music continues under the visual outro and fades at the end. Do not post externally.

You are the visual analyst and editor. Scripts do deterministic processing; they do not understand products. Do not tell the user a standalone script autonomously understands footage. No paid API is required beyond the user's existing Codex session.

1. Check FFmpeg, ffprobe, Bun, runtime, `reels/assets/catalog.json`, and `.cache/kokoro`. If missing, run `scripts/setup-wrydeco-reels.ps1`. Models/audio download once. Check `work/reels-history.json` if present to avoid repeating the last hook and music. Never silently replace Kokoro with Windows speech.
2. Create a unique `output/<date>-<story>-<version>` job. Run `pipeline.py analyze --source <folder> --job <job>`. Inspect inventory errors, then **view every candidate storyboard and photo actually used**. Root Wrydeco source includes reference videos and outro: these are references, not raw footage to recycle. Inspect additional timestamp frames around shortlisted actions if uniform sampling missed an important moment.
3. Read `references/editing-direction.md` for shot roles, continuity, rhythm, motivated effects and layered sound. Group by one product/story. Compare three hook ideas. Write `edit-plan.json` according to the reference. Record concrete evidence for every selected shot and every narration claim. Never infer mass-production status, sustainability, wood species, durability, or origin without evidence. No filename-based selection. If footage cannot support a coherent film, explain what is missing rather than fabricating it.
4. Read `references/audio-discovery.md` and `references/audio-sources.md`. Search the user-selected repositories for sounds matching observed actions and chill music, using the source router plus actual web searches; record provider results and access limitations. Research fresh, region-specific trend evidence before choosing audio. When verified direct-download candidates are found, write `audio-downloads.json` and run `reels/audio_discovery.py --job <job> --region <market> --download` to acquire them automatically before ranking; inspect the download report. Otherwise omit `--download`. Rank licensed local candidates, avoid recent repeats and separate actual observed tracks from style matches/fallbacks. Choose chill music and SFX by mood and visual action, not trendiness alone. Listen if supported. Consult asset provenance and include attribution in caption when required. UI beeps, game reward sounds, unrelated noises and constant whooshes are not suitable. Use wood sounds only as editorial accents or synchronized with a visible contact, not as fake documentary evidence.
5. Run `validate`, then `reels/editorial.py --job <job> --inspect`. View the selected-range sheets (half-second samples plus final frame), and inspect `editorial-audit.json` for repeated-looking photos and long still runs. These are advisory flags, not retention scores: image-only briefs can legitimately use stills. Prefer a meaningful action hook when available; do not replace one repeated photograph with a differently named copy. Then run `voice`. Voice timings are measured, not estimated. On overrun shorten copy, keep pauses, regenerate. Use 2–3 short narration phrases with breathing room. `brand_pronunciation` defaults to `Rye deco`, a provisional pronunciation to assess in the first listening review; never call it owner-approved without evidence.
6. Run `prepare`. View rendered scene frames at effect start/middle/end to verify crop, timing and text placement. The renderer supports cut and 0.4s fade, eased push-in, constant-speed visual retiming, timed top/bottom titles, crop offsets, contrast and saturation. Use the optional `effects` fields documented in the edit-plan reference and justify each effect. Prefer motivated cuts; reserve fade for a slower reveal. Variable speed ramps, tracking, masking and stabilization are not implemented; never silently substitute a different technique and claim success.
7. Run `export`. It launches a dedicated OpenCut on port 3037, assembles via MCP, sets canvas/fps explicitly, exports, and closes its own processes. The original browser render is `opencut-export.mp4`; a final conform pass preserves its video frames while adding square-pixel metadata and normalizing the exported audio with AAC headroom into `reel.mp4`. Render one job at a time. On a stale lock, inspect the recorded PID; remove only a confirmed stale `work/reels.lock`. Do not kill unrelated processes or delete user caches.
8. Run `qa`. View `storyboard.jpg` from the final export, inspect transitions and the outro, and listen to `listen-start.wav`, `listen-middle.wav`, `listen-end.wav` if the environment can actually hear media. Waveform/loudness is not a substitute for judging voice and SFX quality. Review the full mix when a cue or pronunciation is uncertain.
9. Record review JSON (see reference), then run `review --review-file <path>`. Maximum two creative correction rounds; keep failed outputs and explain remaining issues. If listening is unavailable, mark it unavailable and return `needs_review`, never “fully approved.” Technical success alone is not editorial approval.
10. Return Vietnamese links to the Reel, storyboard and caption; state duration/audio layers, actual checks and limits. Tell the user the supplied caption contains required music credit. Do not claim guaranteed Facebook reach, retention or immunity from automated rights claims.

Example command (replace command/job as each stage progresses):

```powershell
.\.venv-reels\Scripts\python.exe reels/pipeline.py analyze --source 'D:\media\new-batch' --job 'output/2026-10-08-bench-v01'
```

Quality bar: hook within 2s; one coherent product; readable text with clear product visibility; purposeful variation in shot length; voice with breathing room; no source audio whatsoever; chill music ducked under speech; SFX sparse and synchronized; no truncated words; complete outro without doubled audio. Files remain local except contact sheets inspected in the Codex conversation and first-time downloads.
